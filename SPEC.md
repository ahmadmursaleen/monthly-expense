# SPEC: Monthly Expense Dashboard

Source: `BRIEF.md`. Architecture and conventions: `docs/ARCHITECTURE.md`, `AGENTS.md`.
Status: **approved 2026-10-06**.

## 1. Goals

**Product:** a local, single-user web app to record expenses and browse spending month by month, with
a downloadable monthly PDF report.

**Dry run:** this project validates the Taskflow workflow end to end. It succeeds when:
1. The board (~2–3 h of work) is completed by **2 autonomous agents** on one laptop, without a human
   touching code. Holds are allowed but should be rare and explained.
2. Every implementation task went through the quality gate (AGENTS.md): a `reviews/tests-*` and
   `reviews/review-*` report exists for it, and a `reviews/fixes-*` report wherever findings were fixed.
3. Every frontend/UI task used the `frontend-design` skill; backend-only tasks did not.
4. `.taskcheck` passed on every `done`, and the final smoke task passes on `main`.
5. The demo script below works on a fresh clone.

## 2. Demo script (what "done" looks like)

1. Fresh clone → `npm install` → `npm run seed -w backend` → start backend and frontend → open
   http://localhost:5173.
2. The dashboard opens on the **current month** (e.g. "October 2026"): total spending, category bars,
   and the transaction list, newest first.
3. Click **Previous month**: "September 2026" with its own totals and transactions. Click **Today** to
   return.
4. **Add expense**: leave the description empty and enter amount `0` → inline validation messages.
   Fix it: "Groceries", `42,50`, Food & Groceries, today → the expense appears at the top, and the
   total and bars update.
5. **Edit** it to `45,00` → the totals update. **Delete** another expense (with confirmation) → it disappears.
6. Type "groc" in **search** → the list narrows. Pick the category filter "Transport" → the list narrows
   further, with a "no matches" empty state if nothing fits. The total and bars still show the full month.
7. **Download PDF** → `expenses-2026-10.pdf` with month, total, category totals, all transactions of
   the month (unaffected by the filters) and the generation date.
8. Navigate to an empty month (e.g. January 2026) → empty state; the PDF still downloads and says
   "No transactions this month."
9. Stop the backend → the UI shows an API error with a retry. Restart → the data is still there.
10. Narrow the window to phone width → the layout stays usable.

## 3. Decisions

| Topic | Decision |
|---|---|
| Stack | Node 22.13+, Express 5, `node:sqlite`, React 19 + Vite, TypeScript 6.0 strict (see ARCHITECTURE.md) |
| Categories | Fixed list, served by the API, no management UI (see §5) |
| Currency | EUR only, formatted with `Intl.NumberFormat("de-DE", {style: "currency", currency: "EUR"})` → `1.234,56 €` |
| Language | English UI and PDF text; numbers and dates formatted de-DE (dates `06.10.2026`). Month titles in English: "October 2026" |
| Money | Integer cents everywhere (API, DB, logic); formatting only at display time |
| PDF | Generated by the backend with **pdfkit**. Content is assembled by a pure function (unit-tested), and pdfkit only renders it |
| Chart | Hand-rolled horizontal bars (CSS/SVG), no chart library |
| Search / filter | Client-side over the selected month's transactions (case-insensitive substring on description; single category filter). **Totals, bars and the PDF always cover the full month**, unaffected by filters *(default, veto if you disagree)* |
| Month navigation | Previous / Next / Today buttons; default is the current month. The selected month is kept in the URL (`?month=2026-10`) so reloads keep it |
| Sort order | Within a month: `date` descending, then most recently created first |
| E2E | No browser tests. Unit/component tests plus a final API smoke task |
| Workers | 2 agents on this laptop → the board needs ~2 parallel lanes |

## 5. Data model

Table `transactions`:

| Column | Type | Rule |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | autoincrement |
| `description` | TEXT NOT NULL | trimmed, 1–200 chars |
| `amount_cents` | INTEGER NOT NULL | `CHECK (amount_cents > 0)`, max 100 000 000 (1 000 000 €) |
| `category` | TEXT NOT NULL | one of the category ids below |
| `date` | TEXT NOT NULL | `YYYY-MM-DD`, a real calendar date |
| `created_at` | TEXT NOT NULL | ISO timestamp, set by the server |
| `updated_at` | TEXT NOT NULL | ISO timestamp, set by the server |

Index on `date`. The schema is created by `migrate()` in `backend/src/db.ts` (`CREATE TABLE IF NOT EXISTS`).

Categories (fixed, defined once in the backend and served by the API):

| id | label |
|---|---|
| `food` | Food & Groceries |
| `transport` | Transport |
| `housing` | Housing |
| `utilities` | Utilities |
| `health` | Health |
| `entertainment` | Entertainment |
| `shopping` | Shopping |
| `other` | Other |

## 6. API contract

JSON under `/api`. Errors: `{"error": string, "fields"?: {"<field>": "<message>"}}`.

**Transaction object**
```json
{"id": 12, "description": "Groceries", "amountCents": 4250, "category": "food",
 "date": "2026-10-06", "createdAt": "2026-10-06T08:30:00.000Z", "updatedAt": "2026-10-06T08:30:00.000Z"}
```

| Method | Path | Request | Success | Errors |
|---|---|---|---|---|
| GET | `/api/health` | – | `200 {"ok": true}` | – |
| GET | `/api/categories` | – | `200 [{"id": "food", "label": "Food & Groceries"}, ...]` in the table order above | – |
| GET | `/api/transactions?month=YYYY-MM` | – | `200 [Transaction]`, sorted date desc, then `id` desc | `400` missing/invalid month |
| POST | `/api/transactions` | `{description, amountCents, category, date}` | `201 Transaction` | `400` with `fields` per invalid field |
| PUT | `/api/transactions/:id` | same body as POST (full replace) | `200 Transaction` | `400`, `404` |
| DELETE | `/api/transactions/:id` | – | `204` | `404` |
| GET | `/api/summary?month=YYYY-MM` | – | `200 {"month": "2026-10", "totalCents": 123450, "count": 17, "byCategory": [{"category": "food", "totalCents": 50000, "count": 6}, ...]}`: only categories with spending, sorted by total desc | `400` |
| GET | `/api/reports/YYYY-MM.pdf` | – | `200 application/pdf`, `Content-Disposition: attachment; filename="expenses-YYYY-MM.pdf"` | `400 JSON` for an invalid month |

**Validation (server is authoritative; the client mirrors it for instant feedback)**
- `description`: string, trimmed, non-empty, ≤ 200 chars → "Description is required".
- `amountCents`: integer, > 0, ≤ 100 000 000 → "Amount must be greater than zero".
- `category`: one of the ids → "Choose a category".
- `date`: `YYYY-MM-DD` and a real date (rejects `2026-02-30`) → "Enter a valid date".
- `month`: `YYYY-MM`, month 01–12.

**Amount input (frontend):** accepts `42`, `42,5`, `42,50`, `42.50` and `1.234,56` → cents. Anything
else, or ≤ 0, is a validation error. This is a pure, unit-tested parse function.

## 7. PDF report content

A4, readable when printed in black and white:
1. Title "Expense report: October 2026".
2. Generation date and time ("Generated 06.10.2026 10:30").
3. Total spending for the month and the number of transactions.
4. Category totals table: category, count, total, share %.
5. Transactions table: date, description, category label, amount, newest first; repeats the header on page breaks.
6. Empty month: sections 1–3 shown with total 0,00 €, and "No transactions this month." instead of
   tables 4–5.

Testing: `buildReport(month, transactions, now)` returns a plain data structure (title, rows,
totals) and is unit-tested. The HTTP test checks status, content type, filename, the `%PDF` header, and that an
empty month works.

## 8. Frontend UX

- **Layout:** header with the month title and prev/today/next; a summary card (total, category bars);
  a toolbar (search, category filter, "Add expense", "Download PDF"); the transaction list. On
  narrow screens it is a single column.
- **Form:** a modal/dialog for add and edit. The date defaults to today when viewing the current month,
  otherwise to the 1st of the viewed month. If you save an expense dated in another month, a notice says
  where it went ("Saved to September 2026").
- **States:** skeleton/spinner while loading; an empty month ("No expenses in October 2026", with an add
  button); no filter matches ("No expenses match your filters", with a clear-filters button); an API
  error banner with Retry; field-level validation messages; a PDF error toast if the download fails.
- **Accessibility:** labelled inputs, buttons reachable by keyboard, focus trapped in the dialog,
  sufficient contrast.
- **Visual direction:** decided by the frontend-design skill in the first UI task and then followed
  by later UI tasks (recorded in `docs/ARCHITECTURE.md` under "UI design").

## 9. Constraints

- Scope: ~2–3 h of agent work, 2 workers in parallel. Tasks of 30–90 min each.
- Local only: no deployment, no secrets, no LLM/AI features at runtime.
- `.taskcheck` must stay under 2 min (currently ~12–50 s).
- Data used anywhere (seed, tests, demo) is fictitious.
- Nothing needs a human during the run except held tasks.

## 10. Open questions

None blocking. Defaults above that you may want to veto:
1. Totals, bars and the PDF ignore search/category filters (they always show the full month).
2. The amount upper limit is 1 000 000 € and the description is at most 200 chars.
3. Seed data replaces all existing data (meant for demos only).
